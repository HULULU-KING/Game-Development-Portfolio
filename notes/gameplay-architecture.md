# LostHeart：Gameplay 对象、检测与战斗架构

[返回 LostHeart](../projects/lost-heart.md) · [作品集首页](../README.md)

## 稳定逻辑根与职责分层

玩家、怪物和武器都以稳定的逻辑根作为身份。模型、挂点、移动体、攻击查询体、受击 Hitbox 和交互范围放在子物体中；替换模型或调整判定范围时，不需要改变其它系统保存的根对象引用。

| 对象 | 根节点职责 | 分离的子级职责 |
| :--- | :--- | :--- |
| 玩家 | 输入解释、角色状态、通用运动 | 相机跟随点、双手挂点、交互范围、受击 Hitbox |
| 怪物 | 状态机、通用运动、普通/暴怒参数 | 睡眠/战斗模型、攻击查询体、受击 Hitbox |
| 武器 | `WeaponItem` 身份、唯一 `owner`、拾取入口 | 挂载表现、攻击控制器、查询形状 |
| 虫群 | 群体状态、威胁和整体位移 | 个体生成、局部随机飞行、点光与受击体 |

角色移动体、攻击查询体、受击体和交互范围使用不同职责与 Layer。查询模板 Collider 保持禁用，仅提供可视化的形状和参数；实际移动阻挡和目标 Hitbox 保持启用，避免攻击体参与刚体推挤或角色根被误判为伤害目标。

## 四类空间检测

项目没有用一种碰撞方案处理所有玩法，而是根据问题选择四类检测。这里的分类来自实际实现，不把注册表查询或 Collider 参数读取误写成一次命中。

| 检测方式 | 实现 | 当前用途 | 选择原因 |
| :--- | :--- | :--- | :--- |
| Unity 实体碰撞 | `CharacterController.Move`、`CollisionFlags`、`OnControllerColliderHit` | 地形与墙体阻挡、落地、斜坡、沿墙滑动、怪物冲刺撞墙 | 需要真实阻挡，并复用台阶和坡面规则 |
| 射线/体积投射 | `SphereCast` | 第三人称相机避障和自动拉近 | 为相机保留体积，减少墙角穿模 |
| 注册表候选后的对点检测 | `EntityRegistry` / `InteractableRegistry` + 距离、方向公式 | 交互、玩家交换、怪物索敌、提灯和虫群范围 | 查询的是明确逻辑对象，规则可按状态和朝向变化 |
| Collider 模板主动查询 | `PhysicsQuery.OverlapColliderNonAlloc` | 玩家武器、怪物冲刺和技能命中 | 只在有效窗口扫描，可使用 Capsule、Sphere、Box 并按 Layer 过滤 |

核心玩法不依赖 `OnTriggerEnter/Exit` 或 `OnCollisionEnter/Exit` 驱动攻击与交互。这样命中时机由攻击时间轴决定，交互目标由当前排序规则决定，不受触发器进入/退出时序影响。

## 输入、规则与运动边界

设备输入先进入 `OperationMapping`，再按玩家生成统一的 `PlayerInputFrame`。快照分别保存移动轴、视角增量、持续按住位和本帧首次按下位；角色、武器、交互和相机不直接读取具体硬件。

```mermaid
flowchart LR
  A[键鼠 / 手柄 / 触控] --> B[OperationMapping]
  B --> C[PlayerInputFrame]
  C --> D[角色规则层]
  D --> E[CharacterMoveRequest]
  E --> F[CharacterMovement]
  F --> G[CharacterController.Move]
```

`CharacterMovement` 只负责固定步移动、阻尼、转向、跳跃、重力、坡面、墙体碰撞和击飞；二跳资格、攻击/交互互斥以及角色能否行动由规则与状态层决定。跳跃包含按键缓冲、土狼时间和可站立坡面判断。玩家与怪物共用运动语义，但分别由输入或 AI 状态生成请求。

桌面模式为键鼠加手柄的本地双角色；移动模式只接收触屏快照，并只把输入发给当前选中的角色。单屏/分屏只改变相机布局，不会让两名角色同时消费同一套移动输入。各系统独立持有输入屏蔽原因，关闭一个页面不会误解除其它系统留下的锁。

## 交互与武器事务

可交互对象实现 `IInteractable` 并在启用期间注册。玩家读取候选列表，以水平距离、前后关系和横向偏移计算目标分数，优先选择更近且更接近正前方的对象。检测用球体保持禁用，只提供中心、半径和 Scene 可视化。

拾取按一个短事务执行：先锁定物品和玩家，再决定槽位、写入 `WeaponItem.owner` 并挂到对应手部，下一帧恢复角色操作。这样两名玩家同帧拾取同一实例时只会产生一个持有者。放下武器会统一清理归属、解除父子关系并恢复注册状态，避免物体已经落地却无法再次交互。

主副手切换、单手/双手兼容、玩家间交换都只修改槽位和唯一 `owner`。攻击模块再从武器归属反查输入与行动资格，避免玩家控制器保存每一种武器脚本的专用引用。交换包含发起、等待、同意、取消、超时和冷却状态；挂起请求的优先级高于普通交互。

## 主动命中与统一受击数据

近战时间轴明确区分准备、有效和后摇阶段。进入有效窗口后，攻击组件使用可复用结果数组执行 NonAlloc Overlap；离开窗口立即停止。一次攻击以实际 `IHitReceiver` 作为去重单位，因此同一对象的多个 Hitbox 只结算一次，而同一父节点下拥有独立接收器的多只萤火虫仍可分别命中。

攻击方只生成统一的 `HitData`：命中点、方向、生命伤害、扣光量、三轴击飞速度、攻击者和武器身份。玩家、怪物和萤火虫各自实现 `IHitReceiver`，分别处理扣血、扣光、暴怒、捕获或惊吓，攻击脚本不依赖具体目标类型。

```mermaid
flowchart LR
  A[攻击有效窗口] --> B[NonAlloc 主动查询]
  B --> C[Layer 与 IHitReceiver 过滤]
  C --> D[按接收器去重]
  D --> E[HitData]
  E --> F[玩家 / 怪物 / 萤火虫自行处理]
```

击飞由攻击方生成初速度，受击方再按自身质量换算并交给通用运动模块积分。怪物冲刺在命中、撞墙、达到距离或超时后都能结束，避免只依赖一次碰撞事件而卡死。

## AI、虫群与动态光照

森林怪物状态机覆盖休眠、苏醒、追逐、瞄准、后撤、普通/追踪冲刺、恢复、击飞、暴怒和死亡。AI 只生成目标速度与朝向，位移仍交给公共运动模块。追踪冲刺使用失败次数递增的伪随机分布，减少连续不触发或短时间连续触发，同时让长期比例接近配置概率。

单只萤火虫在群体局部空间内以三轴独立路径飞行；虫群根维护休眠、惊吓和逃跑状态。多个威胁源按距离平方计算总威胁，按距离立方提高近距离来源对逃跑方向的权重，并联动虫群灯光与附近怪物唤醒。

角色和武器的自制 `SkinLit` 材质从光源注册表选择附近 HLL 局部灯，并使用手提灯、祭坛等 HHZ 光源调制结果。手提灯的唯一持有者、光量衰减、受击扣光、捕虫回复、可见点光和怪物唤醒共享同一归属来源。

## 平台切换与资源体积

Android 适配不是只切换 Build Target：项目增加 Desktop/Mobile 运行模式以隔离输入与相机规则，明确 Terrain 使用 URP Terrain/Lit，并修正自制 SkinLit 在移动端对 glTF 法线的解码和低精度归一化问题。

针对 GLB 内嵌 4K 纹理无法直接使用普通平台覆盖的问题，构建流程生成 1K 移动缓存，构建前以同路径派生资源临时替换、构建后恢复原始文件，保持 GUID 与场景引用不变。历史 Build Report 中纹理构建占用由约 **2.3 GiB 降至 166.9 MiB**，开发测试 APK 由约 **827 MB 降至 146 MB**；这些数字用于说明该次构建结果，不作为所有后续版本或设备性能承诺。
