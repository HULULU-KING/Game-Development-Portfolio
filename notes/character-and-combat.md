# 角色控制与动作时序

[返回 TrainingGround](../projects/training-ground.md) · [作品集首页](../README.md)

## 输入和运动为什么分开

渲染帧与物理固定步并非一一对应。按下事件如果直接在每个固定步重复读取，可能重复触发；仅在渲染帧瞬时处理，又可能无法将请求传递给下一固定步。

项目由 Update 捕获按下边沿并缓存请求，由控制器在 FixedUpdate 消费一次。持续移动轴与一次性按下事件分开处理。实际起跳结果由运动模块返回，再分发给动画与反馈模块。

## 三层边界

| 层 | 负责 | 不负责 |
| :--- | :--- | :--- |
| 输入层 | 设备读取、按角色分配、按下边沿和输入屏蔽 | 位移与动画播放 |
| 角色规则层 | 二跳资格、攀爬/施法/攻击互斥、状态恢复 | 底层碰撞实现 |
| 运动执行层 | CharacterController 位移、重力、坡面、转向、击飞 | 输入设备、技能次数和 UI |

公共运动模块以 `HLL.Movement` 程序集及固定版本 UPM tarball 分发。LostHeart 使用 0.1.0，TrainingGround 使用 0.3.0；升级由工程主动选择，避免公共源码变化直接改变两个项目的行为。

## 连击：让姿态与查询使用同一步的数据

`StaffComboClock` 每次推进一个整数物理帧。配置定义动作长度、预读窗口、分支衔接和命中区间；当前动作时间交由 Playables 采样。之后更新武器挂点，再在有效窗口内执行攻击查询，按接收器而不是 Collider 去重。

这种顺序让攻击逻辑使用已经更新的武器姿态。取消攻击时同时清理命中窗口、攻击归属和动作求值模式，避免只停止画面却留下逻辑状态。

这里的“帧”表示 FixedUpdate 次数，因此改变固定步长会改变同一帧数对应的真实时长。它是固定步组织方式，不等同于网络帧同步或跨平台确定性物理。

## 攀爬：保留支撑，规划换点

身体沿规则树干表面移动；支撑点固定在世界空间，换点期间规划手掌和脚底目标。根据上爬、下爬、横移采用不同的手脚先后顺序，并根据肢体可达范围限制身体推进。

进入攀爬时，根位置、朝向和姿态混合共享进入进度；普通移动和 `MoveGuided` 在同一个固定步中择一执行。退出时恢复速度和重力，而不再次叠加一次位移。

## 验证重点

- 同一按下请求只能消费一次；二跳后拒绝第三跳，落地恢复。
- 顶头、陡坡、击飞和松手后的跳跃资格符合规则。
- 抓附进入、绕树与手脚接触在不同步长下保持约束。
- 同一角色连续完成移动、二跳、攀爬、松手、落地与施法。
- 攻击数据按接收器去重，障碍截断后不继续命中墙后对象。

结果及适用范围见 [验证记录](validation.md)。
